# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # start dev server at localhost:4321
npm run build    # build to ./dist/
npm run preview  # preview the production build locally
```

No test suite or linter is configured.

## Architecture

**Stack:** Astro 6 + Tailwind CSS v4 (via `@tailwindcss/vite` plugin). No JS framework — all components are `.astro` files with vanilla script blocks where interactivity is needed.

**Bilingual routing (NL / EN):**
- Dutch pages live at the root: `/`, `/hoe-het-werkt`, `/prijzen`, `/product-tour`, `/over-ons`, `/contact` (`/functies` redirects to `/hoe-het-werkt`)
- English equivalents are under `/en/`: `/en/`, `/en/how-it-works`, `/en/pricing`, etc.
- The NL <-> EN slug mapping is maintained in [src/data/routes.ts](src/data/routes.ts) (`pairs`). It drives both the language switcher in Nav and the `hreflang` tags in BaseLayout. When adding a new page, add the NL/EN pair there and add the route to the `links` arrays in [src/components/Nav.astro](src/components/Nav.astro) for both languages.
- Demo video pages (`/hoe-het-werkt/<slug>`, `/en/how-it-works/<slug>`) are generated from [src/data/demos.ts](src/data/demos.ts); adding an entry there creates both pages, the nav dropdown item and the route pairs. Clips are recorded with `npm run record:demos` (see [scripts/demo-videos/README.md](scripts/demo-videos/README.md)).
- SEO guide articles (`/gidsen/<slug>`, `/en/guides/<slug>`) are generated from [src/data/guide-content/](src/data/guide-content/) (`nl.ts`, `en.ts`). Translations share an `id`; an entry creates the page, its overview card, sitemap entry and hreflang pair. Only claim features that exist in the app.

**Page layout:** Every page wraps in `BaseLayout` ([src/layouts/BaseLayout.astro](src/layouts/BaseLayout.astro)), which accepts `title`, `description`, and `lang` props. `lang` defaults to `"en"` — NL pages must pass `lang="nl"` explicitly.

**SEO:** `BaseLayout` emits canonical (`https://gedekt.com`, trailing slash, matching how the live site serves URLs), hreflang, Open Graph/Twitter tags (default image `public/og-image.png`) and JSON-LD (Organization + WebSite, plus whatever the page passes via `jsonLd`; builders in [src/data/seo.ts](src/data/seo.ts)). The sitemap is generated by `@astrojs/sitemap` at build time.

**Design tokens** are defined as CSS custom properties in [src/styles/global.css](src/styles/global.css) using Tailwind v4's `@theme` block:
- Colors: `--color-forest` (#1B4332), `--color-forest-light`, `--color-amber`, `--color-amber-light`, `--color-cream`, `--color-charcoal`, `--color-stone`, `--color-dark`
- Fonts: `--font-display` (Sora), `--font-body` (Inter) — self-hosted via `@fontsource-variable/*` (imported in `global.css`, Latin subsets preloaded in `BaseLayout`)

**Images:** put images in `src/assets/` and render them with `<Image>` / `<Picture>` from `astro:assets` so they are converted to WebP/AVIF and sized per screen. `public/` is only for files that must keep a fixed URL (favicons, `og-image.png`, videos).

Use `var(--color-*)` in Tailwind classes (e.g., `text-[var(--color-forest)]`) rather than hardcoded hex values.

**i18n pattern in components:** Components that appear on both NL and EN pages (Nav, Footer) accept a `lang` prop and define a `t` object with both translations inline — no external i18n library.

**App URL:** The live app is at `https://app.gedekt.com`. CTAs and login links point there.
